# 农场素材尺寸、占位与四季规范

这份规范把农场素材的**像素绘制范围、地图占地、碰撞、交互点和季节变体**分开描述。概念稿可按已确认批次集中提交审阅；每类转成正式图集后，仍须通过格线、角色比例、锚点和碰撞核对，才登记为可集成素材。

## 基础格与比例

- 世界基础格固定为 **32×32 世界像素**。素材规格 JSON 是尺寸基准：`farm_asset_contract_v1.json`。
- `visual_size_tiles × 32` 得到预期绘制像素范围。例如水井按 **3×4 格**设计，素材目标尺寸为 **96×128 px**。
- 所有高物件以底部中心的接地锚点对齐。树冠、井架、屋檐等高出地面的可见部分可以跨过可行走格；它们的透明画布或可见轮廓不等于碰撞体。
- 地图放置数据分别保存视觉矩形与 `blocked` 碰撞矩形。碰撞按该素材实际接地的硬质底座/树干等轮廓，对 32×32 格逐格描出占格掩码并计数；禁止按素材类别套固定占地、从图片边界自动推导整张图大小的碰撞，也不允许为了适配碰撞格而把像素素材拉扁或拉长。
- 碰撞以人物脚底/身体实际会撞到的区域为准；交互范围另列为可站立格。门前、井边、箱子正面等必须有可达交互格。
- 渲染遮挡深度使用物件的接地基线，而不是精灵顶部。主角经过树冠、屋檐、井架时，前后遮挡可正确切换，但碰撞仍只发生在明示的实体占格。

## 水井尺寸示例

| 属性 | 规格 |
| --- | --- |
| 基础格 | 32×32 px |
| 可见素材 | **3×4 格，即 96×128 px** |
| 实体碰撞 | 逐格描出石质底座与地面接触的实地占格；格数和掩码待最终 3×4 素材按基础格对齐后登记 |
| 接地锚点 | 石质底座实际接地边的中心 |
| 可交互站位 | 根据登记后的碰撞掩码，在可走的相邻格显式定义 |

井架/屋顶高出并宽于底座，属于非阻挡的可见外挑。按最终 3×4 精灵的接地石基校准后，当前水井碰撞为底部 3 格宽、1 格深，共 3 格；正面交互格留在碰撞区外。后续若替换井图，需重测石基而不能沿用旧占位。

树木同理：树冠可见范围与树干/根部实地碰撞分开测量。花丛、草束等小装饰可不阻挡；树干、建筑基础和石基需要按各自实际接地占格描掩码，不假设它们必然是 1×1 或 2×2。

## 农舍成长的三级尺寸

三级规格已写入 JSON，按**可见外轮廓目标**区分为 9×8、11×8、13×9 格。初始农舍的石基已按运行素材测为 8×1 格；扩建与大型版本仍须等正式轮廓按网格对齐后逐格描出掩码。门前格独立于建筑碰撞登记。升档只扩大或调整房屋实体/视觉数据，不应把人物、全图地图格或镜头倍率一起缩放。

后续每一级农舍都要单独确认：屋顶和墙体轮廓、门的局部坐标、底部碰撞范围、室内外门传送点、门前空地、人物身高对比。老资产可以作为原型，但只有画布宽高比与目标一致时才能映射到对应等级。

## 四季资产要求

农场地图的季节变化采用四套一致的资源规格：**春、夏、秋、冬**。JSON 中列出每季的色彩方向及必须覆盖的素材类别。

- 地面、岸边与水体需要有四季变体；变体不能改变可走/不可走分类。
- 树木保留树干锚点与碰撞，树冠按季节呈现嫩绿/浓绿/秋叶/落雪或常绿。
- 作物继续按对应季节的生长图集展示；季节切换不能造成作物贴图或格子位置跳变。
- 农舍与常驻道具保留主体结构，用四季屋顶、窗边花草、落叶、积雪等独立变体/覆盖层表达季节。
- 四季替换必须保持相同格尺寸、接地锚点、碰撞和交互位置。冬季水面仍不可通行；结冰规则若要改变导航，必须作为单独玩法显式定义。

### 当前农场地表图集

- 农场地表以 `source_generated/farm_terrain_user_seasons_source_v1.png` 为素材源，经逐项裁切后运行时使用 `runtime_generated/farm_terrain_user_tiles_v1.png`。
- 运行时每一块严格为 **32×32** 方格，四季各一行；路面连接形、干/湿耕地和水面分别裁成单格，不把整张松散排布的原图按等间距硬切。
- 地表方格只影响视觉，不缩放导航格，也不改变通行碰撞。草地继续用连续底纹，用户图集切块叠加在对应格子上，避免方块间露出空隙。
- `tillable` 代表这格允许锄地，不代表初始时已被翻土。未翻地显示季节草地；翻地后才显示图集土壤，浇水后切换湿土样式；种植物仍由作物生长图集覆盖。
- 土路依相邻道路格连接关系生成 32×32 范围内的直路、转角、T 形与十字轮廓；先统一绘制连续外沿，再绘制路面与颗粒纹理。弯道和 T 口按照邻接方向旋转，接边宽度、季节色板保持一致。

## 已确认方向后的正式制作顺序

上一轮已确认整体风格方向，并完成建筑、季节场景、院落道具、地表、作物/果树和动物概念板。概念板只确认大方向，不能证明每个局部轮廓、数量、像素尺寸或季节细节都已定稿。按以下顺序逐组细化：

| 制作组 | 正式输出 | 每件素材的固定数据 |
| --- | --- | --- |
| 1. 地表 | 草、土路、水岸、耕地/浇水地四季图块与转角/边缘连接件 | 单格 32×32；连接拓扑、通行分类、季节 atlas 索引一致 |
| 2. 农场小道具 | 井、箱、邮箱、稻草人、洒水器、围栏、门、槽、宠物碗、蜂房、灯、杂物 | 声明像素画布；根锚点；底座实占掩码；交互格；季节覆盖层 |
| 3. 作物与树 | 与游戏种子 ID 对齐的作物阶段、枯死帧、藤架成熟态；普通树和果树阶段 | 单株地面格、每阶段同根锚、成熟/收获状态、藤架阻挡标记、树干掩码和四季树冠 |
| 4. 动物 | 鸡鸭、牛羊猪、马、猫狗的待机/行走图集 | 角色高度参照；统一脚底线；方向和帧数沿用现有动画播放逻辑；动物碰撞与门宽分别登记 |
| 5. 建筑 | 农舍三级、鸡舍/畜棚升级、筒仓、温室修复态、储物棚、马厩、磨坊、鱼塘 | 可见尺寸、基础掩码、门位/交互位、深度锚点、季节外观逐项登记 |
| 6. 地图 | 标准农场首日布局与四季截图，再扩展主题变体 | 基础格导航图、出生点、出口、建筑地基、可耕地、可建区和连续可走路径 |

正式候选按组提交，不从概念板自动切成最终 sprite。每组的碰撞掩码只根据成品图的实际地面接触部分绘制；未核实前 JSON 中 footprint 必须保持 `null` 并标注 pending。

### 动物行走帧的防平移要求

鸡、鸭、牛现有运行时图集使用 **4 列 × 4 行**（每方向 4 个步态相位，行序 down / left / right / up），并按实际漫步距离推进帧。动物新行走素材遵循 `assets/art/ANIMATION_CONTRACT.md` 的固定根锚与步态原则，同时维持当前四帧运行契约；不能为了模仿主角的 8 相位图集而擅自改变运行代码或贴图布局。

- 同一动物四帧使用完全相同的格宽高、躯干中心、脚底基线、可见体型和投影中心；不得逐帧平移整只动物、自动裁切后重新居中或缩放。
- 四帧依次表达接触、承重/轻微下沉、对侧腿经过、回收到下一次接触。帧 0 是稳定站立/可停姿势；停止移动时回到该帧。
- 只让腿部做短步交替，头部、耳朵、尾巴和身体最多小幅摆动；抬脚高度、左右摆幅和身体上下起伏都要克制。身体根锚横向漂移为零，支撑脚相对根锚不跳动，摆动脚只在腿部区域清楚离地。
- 帧间只改必要的姿势像素，保持毛色斑纹、轮廓、头身比例、朝向和阴影位置稳定。不得用整只动物横向位移制造走路，也不得出现一帧腿迈很远、下一帧突然收回的跨度。
- 将四帧并排逐帧对照/循环播放检查，再与动物的实际移动速度、步长对应。动画推进继续按实际行走距离驱动；若画面滑动，先校正支撑脚、锚点和步幅节奏，不靠增加速度或整体移动精灵补偿。

当前动物动作概念板只供体型参考，不能直接作为动作验收结果；正式行走候选必须展示同一物种固定画布内的四向四帧小步循环。

### 公母动物成对设计

- 鸡、鸭、牛、羊、马、狗、猫都尽量提供公母两种外观/角色变体；优先在物种容易辨认的特征上做差异，例如羽色/鸡冠、体型和乳房/角、鬃毛与头部轮廓、毛色斑纹。
- 同一物种公母变体共享像素风格、方向/帧序、画布尺寸、根锚、脚底线和运动幅度。公母身形可有小幅合理差别，但各自的整套行走帧都必须保持帧间稳定。
- 差异应自然、清楚但不过度夸大；狗猫不强行套用明显外形刻板印象，采用轻微体格/脸部/毛色变体，并在游戏数据中单独记录性别，不能只凭外观判断。
- 每个性别变体都要有完整待机和行走方向；不能只给其中一个性别画完整帧集，另一个只作为换色静态图。

## 生成与验收次序

1. 以 32 px 世界格和玩家当前 44 世界像素可见身高设置房屋/物件/人物比例。
2. 透明背景、硬像素边缘、无文字与水印。概念稿可成组审阅；确认具体素材后才裁格、修透明、命名和接入。
3. 检查实际画布尺寸、格线、透明度、像素密度和纵横比；确认没有为匹配碰撞而拉伸素材。
4. 将视觉矩形、局部碰撞矩形、接地锚点、交互站位和季节资源逐项登记在配置与地图数据中。
5. 在同一镜头倍率下观察人物、井/树/农舍之间的相对尺寸；走到物件旁检查碰撞、绕行和交互，再检查四季变体位置稳定。

《星露谷物语》只作为高层视觉参照：暖色乡村调色、清楚的像素簇、丰富但不抢主体的地表细节、俯视农场的层次与可读动线。角色、房屋造型、地图布局与图块都保持花溪原创。现有地图仍以 `design/maps/outdoor_navigation_v1.json` 的导航与碰撞为准；本规范配置的是新素材制作尺寸，不会自动覆盖未确认的现有图集。
