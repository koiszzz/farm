# 花溪农场：操作、加载与五区域改进规划

调查日期：2026-09-21。范围：当前工作区代码、角色原始图集、已有游戏截图、Godot 无窗口性能采样、星露谷官方截图与场景资料。本文件保留最初调查结论；后续实施与验证记录见 `IMPLEMENTATION_PROGRESS.md`。工作区原有 game.gd、life_system_test.gd 修改保留。

## 1. 结论与明确需求

优先顺序：出屋性能 → 自由移动与镜头 → 动画与交互 → 五区域内容。

- 当前手感的首要问题是整格移动约束；增加动画图片不能解决松键、转向延迟。
- 主角已有四方向各 8 帧行走图，但有效姿势变化不足；NPC 是四方向各 4 帧。文档中的 4×3 旧契约已经失效。
- 出屋会同步重建 NPC 导航、场景缓存和宠物导航。实测同步切换平均 8.48 秒，其中 NPC 占约 75%。
- 主场景规划为农场、沙滩、小镇、山洞、郊区。区域必须有独立玩法、辨识度和往返目的。
- 镜头整体拉近，首轮比较 1.5× 与 1.75×，以 1.5× 为起始方案。
- 地面不得绘制地点文字；人物头顶不得显示文字，包括互动提示和短暂奖励飘字。地点信息通过可阅读的实体路标呈现，人物姓名进入对话框后显示。

## 2. 已确认的代码原因

### 移动与动画

`scripts/game.gd:507` 的 `_update_player_movement()` 先走完 move_target，再在下一格读取方向；`_begin_move()` 每次目标固定为相邻格中心。普通步行 32 / 0.25 = 128 世界像素/秒，跑步乘 1.65。松键或转向理论上最多要等约 250ms（跑步约 152ms，另加帧调度），表现为人物沿格子滑动。

`_pressed_direction()` 使用 A、D、W、S 固定优先级，只返回单轴方向，不能斜走；碰撞失败还会回退到上一确认格。虽然已有 CharacterBody2D，实际仍直接设置 position，而不是自由速度运动与滑动碰撞。

`avatar_renderer.gd:184` 读取 8×4 图集，`advance_stride()` 已按实际位移推进步态，值得保留。game.gd 中旧 walk_a/walk_b 时间切换不是实际只有两帧的证据。当前走路周期为 64 世界像素，跑步为 80，数值与新素材的落脚距离应一起校准。

目视 `farmer_walk_v2.png`：侧面多帧反复出现相近的大跨步姿势，中间收腿/经过姿势不够清楚。后续量化确认每方向已有8帧，但最接近帧相似度为0.9423–0.9595；下/左/上三行的脚中心横向变化约30–33源像素，上行轮廓脚底高度还变化16像素。原图1774 × 887也不能被8 × 4整除。详见 `qa/2026-09-21/animation/frame-analysis.md`。这证明首要问题是关键姿势重复、格子和锚点不一致，并非单纯帧数太少。逐帧根据最低不透明像素寻找脚锚点，也可能把摆动脚造成的变化变成身体抖动，应改为离线审核后的固定锚点元数据。

### 出屋加载

链路：`_enter_door()` → `CenterLightTransition.play()` → `_change_map()` → world.configure / 强制流送 / NPC 重建 / 宠物重建。

| 项目 | 当前行为 | 后果 |
| --- | --- | --- |
| NPC 导航 | `_npc_walk_route()` 对每个 NPC 新建 AStarGrid2D，遍历 248×112 格 | 早上 10 人反复处理约 27.8 万格，再计算路线 |
| 宠物导航 | 每次切换地图 rebuild_grid，包括不可见时 | 返回户外再遍历 27,776 格 |
| 场景缓存 | configure 换图清空对象和地形缓存 | 从室内返回也重新创建 |
| 加载中心 | configure 先用默认出生点，随后流送到实际出口 | 从镇上出门可能额外准备无用的农场附近块 |
| 地形粒度 | 2×2 格一个节点，强制同步建立 | 本次农舍出口得到 1,134 个块节点 |
| 门索引 | 每次 configure 扫全图寻找门 | 可在地图导入时一次建立 |
| 数据复制 | get_map() 深复制完整地图，渲染器多次只为读取 objects 调用 | 不必要的地图级分配；独立占比尚未测量 |
| 转场动画 | 出屋固定 0.16+0.04+0.50 秒 | CPU 阻塞叠加在约 0.70 秒动画上 |

## 3. 优化方案

1. 每张区域地图建立一份静态可行走数据；NPC 共享静态导航，巡逻路线按地图版本、路线节点缓存。动态障碍采用版本号失效或局部更新，避免不同角色互改共享网格。
2. 常驻当前区域和最近室内场景；进入房屋时暂停并隐藏户外表现，返回时恢复。设置缓存上限，并验证内存多次往返后不持续增长。
3. configure 接受最终到达点，先准备可见地形与脚下碰撞，外围准备按每帧时间预算推进。主线程节点创建分帧；不把场景树操作直接扔到工作线程。
4. 导入期建立门、物件、地形索引。添加只返回物件数据的接口，避免为 objects 深复制完整地图，也不向调用者暴露可随意修改的地图内部字典。
5. 宠物导航按地图和障碍版本复用；不可见时跳过重建。日程变化只更新实际改变的 NPC，不销毁重建所有居民。
6. 对 4×4、8×8 地形块与 TileMapLayer 做同场景对照；2×2 粒度曾用于解决行走尖峰，不能未测量就直接改大。
7. 最后再校准淡入淡出时间。单纯缩短黑屏、添加加载提示或异步读贴图无法消除本次主要 CPU 成本。

目标（待实现验证）：暖返回从触发到可操作 ≤0.8秒，冷返回 ≤1.5秒；行走60FPS目标下 P95≤16.7ms、P99≤25ms。需要发布构建、真实渲染、至少30次往返复测并记录机器配置。达不到目标则按阶段计时继续定位，不以播放动画遮住长时间阻塞作为验收。

## 4. 移动、镜头与交互设计

- 用归一化二维输入和 CharacterBody2D.move_and_slide 实现连续位置移动；格子仅承担耕作、工具目标、地图数据的索引。对角线不能比直线快。
- 起步、松键、转向在下一物理帧响应。默认直接响应输入，不引入明显惯性；轻微加减速仅作为对照项。
- 保留脚底碰撞盒并检查墙角滑动；堵路时原地停止，不回弹到上一格。不在镜头或视觉取整时修改真实物理位置。
- 朝向取最后有效输入；斜走时采用稳定的主轴规则。步态依据实际移动距离推进，碰墙不原地走路。
- 工具保留单次落点结算，增加有限输入缓冲；动作分准备、接触、恢复阶段。现有浇水0.95秒、送礼0.90秒等锁定时间需试玩调整，而不是全部动作统一加速。
- 镜头当前未设置 zoom，默认1.0；在1280×720逻辑视口，1.5×约显示26.7×15格，1.75×约22.9×12.9格，均未扣HUD。先统一放大世界，再看人物与建筑比例。
- 比较关闭跟随平滑与当前10.0平滑速度；避免角色启动时镜头追赶掩盖位移。室内小地图需单独居中/限位，不照搬户外边界。
- UI保持独立CanvasLayer；精简顶部大条与常驻操作说明。像素画统一采样尺度，检查分数缩放下闪烁；不要只把主角Sprite放大导致门和NPC失衡。
- 统一交互目标选择：距离、朝向、可达性/遮挡、显式设施优先级；屏幕固定位置提示当前目标，按键行为必须与提示一致。当前NPC只按距离找最近者，需增加遮挡校验。
- NPC靠近时朝向玩家，确认对话后锁定目标；聊天中暂停相关移动。修正所有居民换日程时一起重生造成的位置跳变。

### 地面和头顶无文字

现有入口：`world_renderer.gd::_draw_wayfinding()` 直接绘制地面文字牌；`_draw_festival_bunting()` 绘制节日提示；`world_feedback.gd::_draw()` 在玩家头上绘制 `_context_text()`，并绘制动作奖励飘字。

替换为立在路边的木质/石质实体路标，有底座、阴影、遮挡排序及合理碰撞，表面仅保留箭头/图案。路标作为独立 interaction 记录，靠近并按F后打开阅读面板：地点名称、简短介绍、相邻区域方向、当前可做的事。实体不要占道路中心，触发范围与画面一致。地图生成合并须保留路标记录。

姓名、职业只在对话窗口或居民面板出现；动作文字改为固定HUD短消息或物品图标反馈；人物上方保留必要的非文字情绪图标需统一风格。正式游玩所有区域、节日和动作状态均验证无地面/头顶文字。

## 5. 动画资产改造

先完成一名主角的小样：四方向、每方向6～8个有意义的行走姿势；关键是接触、承重、经过、抬脚的节奏连续，而不是自动插帧数量。跑步要有独立腿幅/摆臂节奏。先沿现有8帧接口替换便于对照。

固定角色高度、头身比例、骨盆轴、地面线和左右脚锚点；制作无背景图集时避免每帧改变服装细节、轮廓和比例。将脚锚点、手握点、工具接触点写入离线元数据，替代运行时扫描透明像素猜测。

先测试慢走、跑步、反向、停步、贴墙、四方向工具动作，再扩展NPC。同步更新 `assets/art/ANIMATION_CONTRACT.md`，把旧3方向2步态文档改成真实契约。不把过时文档当现有功能缺失。

## 6. 五区域世界规划

推荐采用有明确出口的五区域架构，室内为附属场景；邻区可预热，但不要求整张世界同时加载。当前仅 farm_outdoor、town_square、riverside 合并为 valley_world，沙滩和矿洞需要真正新增内容，不能仅把河畔改名。

| 区域 | 场景构成 | 最小玩法闭环 | 边界/标志物 |
| --- | --- | --- | --- |
| 农场 | 农舍、田块、出货点、仓储、动物预留区 | 种植→浇水→收获→出售→扩建 | 篱笆、果树、田埂、出入口路标 |
| 小镇 | 广场、社区会堂与修复、种子店、诊所、咖啡馆、住宅、工匠服务 | 采购→委托→捐献修复→社交→升级 | 铺装变化、桥、钟楼/大树 |
| 沙滩 | 海岸、沙丘、潮池、码头、渔屋 | 拾贝→海钓→出售/交付 | 海浪、岩礁、码头灯，不复制河流地形 |
| 郊区 | 林间道路、溪流、木场、山脚、野生资源 | 采集→清障→修桥/解锁道路 | 林缘、坡道、溪桥、山洞路标 |
| 山洞 | 入口营地、矿层、梯子、返回点 | 挖矿→消耗体力→带回矿石→工具升级 | 岩壁、矿脉、光源、楼层出口 |

建议拓扑：农场↔郊区↔小镇；小镇↔沙滩；郊区↔山洞。后期农场至小镇解锁捷径。每区入口必须提供明确视觉地标和可阅读路标；主要设施间路程以试玩调整，不追求面积最大。

先做有限区域切片：农舍出门、田地劳作、经郊区到镇上购物、与一位居民对话、返回睡觉。山洞首版只做少量可完整往返的矿层；战斗、装备、复杂楼层生成留到挖矿/升级闭环稳定后。

迁移必须同步处理：存档 map_id+区域局部坐标、农田单元持久ID、入口返回点、NPC日程、采集物位置、宠物家位置和大地图。旧 valley_world 坐标先按区域偏移转换；旧缓冲区位置映射到郊区或最近安全出口。保留存档备份，做版本迁移与二次读取验证。

据此建议把下一批环境工作排成三件事：先为海岸加入轻量循环浪纹/泡沫，不移动碰撞和采集数据；再为洞穴加入分层色温与火把动态光，让入口、普通矿层和深层一眼可区分；最后降低郊区草地重复纹理的对比度并增加成组植被/季节小物。镇区继续补住宅、花坛与居民路线，农场继续补可交互庭院设施。文字仍只出现在HUD、菜单/对话和按键阅读路标里，地图地面及人物头顶不绘制地点名、角色名、互动字样或奖励飘字。

### 界面与生活资产补充方向

以官方画面中的清晰地标、低对比地面、醒目物件轮廓和独立菜单层次作为构图参照，所有贴图与图标保持花溪自己的设计。旅行地图用纸本边框、地貌色块和出口标记展示农场、郊区、小镇、沙滩、山洞；可显示地图标题和地名，场景地面仍不出现文字，地点说明只通过实体路标打开。

旅行手册全域页现使用原创像素谷地图作为底图，正式区域拓扑与 `RegionWorldBuilder` 的物理出口一致：农场—郊区—小镇，郊区向北到洞穴、向南到海滩；当前区域通过存档地图ID映射高亮，室内和矿洞楼层也归入所属户外区域。点击下方区域按钮只切换对应的详细地图，不会瞬移玩家。

背包以物品格、快捷栏和单独的物品说明为核心；角色卡显示当前外观、季节日期、金币、体力、生命和技能成长；设置把显示选项与按键提示分组。后续如加入音量、按键重设或无障碍选项，必须先有真实可用的运行时设置数据，避免只有装饰控件。

场景资产按生活循环拓展，并坚持像素尺寸、脚点锚定、描边与调色板统一：家具从床、桌椅和壁炉扩展到储物柜、工作台、餐桌及院落装饰；植物从当季作物扩展到四季果树、花卉、灌木和可采集植被；动物区分幼年/成年、站立/行走/进食/互动等动作；各区用专属地面、边缘和地标小物形成识别度。每批新增资产先记录图集格序、透明边界、锚点和运行时映射，再接入场景，避免只增加数量却破坏辨识度。

### 音乐与声音

音乐需使用原创主题与旋律，不复用《星露谷物语》曲目。按五个主区域设计可辨识但音量克制的循环：农场温暖舒展、郊外自然流动、小镇更有活力、海滩开阔、矿洞稀疏幽暗；室内可使用更轻柔的变体。区域、季节、昼夜和节日变化采用交叉淡化，循环首尾避免突兀，设置页音量即时生效并保存。动作音效与背景音乐分层，使用单独音量控制；进入对话、菜单、钓鱼时再按体验决定是否压低音乐。音乐应经过实际扬声器/耳机试听、循环点检查与长时间游玩测试后才能验收，代码生成的波形可先用于实现闭环，不能代替最终编曲与混音。

## 8. 分阶段执行与验收

| 阶段 | 工作与产物 | 验收重点 |
| --- | --- | --- |
| P0 加载 | 共享静态导航、缓存路线、目标入口加载、门/物件索引、往返计时 | 农舍及镇上3类室内往返；早晚/雨天/节日；首帧与可操作时间；内存稳定 |
| P1 操作小样 | 自由移动、斜走、镜头1.5×/1.75×对照、主角四方向步态 | 松键/反向下一物理帧响应；斜走等速；无回弹；脚部无明显滑步；镜头无抖动 |
| P2 交互与视觉 | 实体可读路标、清除世界文字、统一目标选择、NPC朝向/对话 | 地面与头顶无字；提示与目标一致；墙后不能对话；门不被NPC抢占；工具仅结算一次 |
| P3 五区首版 | 区域数据、出口、地图UI、存档迁移、邻区缓存 | 五区全可达可返；无出口循环；旧档农田/背包/居民关系保持；各区至少一个可重复活动 |
| P4 生活深度 | 矿石→工匠→工具升级；沙滩专属鱼/采集；NPC地点对白与日程 | 外出带回资源能改善农场；连续数日有明确目标；先深化现有系统，再扩展数量 |

结构上逐步从 game.gd 提取 PlayerController、WorldSession、NavigationService、InteractionResolver、CameraRig；每个阶段只迁移其需要的责任，不先做与体验无关的大范围重构。

回归沿用并调整 movement_input、navigation_motion、action_system、door_transition、world_travel、continuous_world、spatial_consistency、life_system、farm_state 等现有测试。自由移动后，旧测试对整格停靠的假设应改为输入响应、碰撞和工具目标的行为验证。性能专项必须启用 force_continuous_world_for_qa，否则 autosave_enabled=false 会让部分测试落到小地图而漏掉大地图瓶颈。

最初调查的5次采样成功退出。后续实现、回归范围、真实渲染结果和仍未完成事项持续记录在 `IMPLEMENTATION_PROGRESS.md`，不以本文件末尾状态代替当前进度。
