# 固定脚步锚点实机检查

旧渲染器会将每个行走帧的整个人物重新对齐到当前最低脚部的横向中点。v5 正面行走图集的这个点横跨 68 个源图像像素；按运行缩放约为 11.7 个世界坐标单位、1.75 倍镜头约 20 个屏幕像素。脚在左右交换时，头和躯干也跟着侧移，可能形成“滑行”的观感。

现在行走图集按朝向共用固定根锚：X 固定在 192px 单元中心，Y 使用该行八帧不透明脚线的中位数。被裁掉的透明边界仍按固定根位置换算偏移；碰撞、世界坐标、速度、输入响应和工具动作结算不变。地面椭圆阴影仍锚在人物物理根上。

更新后四向八相位与跑步列阵由 Windows / Godot 4.7.1 / NVIDIA RTX 3050 D3D12 实机帧缓冲捕获：`fixed-anchor-walk.png`、`fixed-anchor-run.png`。`avatar_rendering_test.gd` 67项0失败，覆盖全部32个帧的可见高度和同方向固定根锚；`movement_input_test.gd` 行走/奔跑、下一物理帧停步与反向、斜向同速、贴墙滑行均通过；`action_system_test.gd` 和 `game_smoke_test.gd` 通过。

这项修正解决了可量化的渲染偏移来源，不足以证明完整的人体步态已完成真人手感验收。此前跑步仍复用行走图集。

## 独立跑步动作

随后增加 `assets/art/runtime_generated/farmer_run_v3.png`，不覆盖原行走图。画布为1536×1024，8列×4行，方向顺序与行走素材一致。`avatar_renderer.gd` 在移动且按住 Shift 时切换跑步图；帧仍按真实移动距离推进，使用同一固定根锚和 nearest/clipped 区域渲染。

`run/final-analysis.json` 记录完整单元范围和相似度。D3D12四向八相位实拍仍用 `fixed-anchor-run.png`，可以看到侧向摆臂和更大的腿部跨步；行走对照是 `fixed-anchor-walk.png`。`avatar_rendering_test.gd` 135项0失败，覆盖跑走选择、32个跑步相位的固定根锚和统一显示高度；`movement_input_test.gd` 报告行走27.73像素、跑步45.76像素，动作与游戏启动回归均通过。

图集仍有12个不透明像素落在纵向单元边线上，由渲染器区域裁切避免串格；前向个别相位也有轻微腾空高度变化。实拍显示当前人物可读，但边线清理和玩家实控手感仍需继续复核。

## 停步与受阻后的落脚相位

本轮发现 `stride` 在停止时保持原值，再次移动可能从抬脚帧开始，造成脚部“弹”入步态。现在松键或受阻且无实际位移时，主角回到相位0（落脚姿势）；连续移动中的换向与步态仍按实际距离推进。`movement_input_test.gd` 新增顶墙后落脚及松键重置断言，0失败。`avatar_rendering_test.gd` 135项0失败，`navigation_motion_test.gd`、`action_system_test.gd` 和 `game_smoke_test.gd` 均通过。

逐帧数据见 `walk-frame-analysis.json` 与 `run-frame-analysis.json`。当前主角走、跑都是每方向8帧；本轮证据不支持把帧数不足当作首要原因。步行各方向测得的最低脚线范围为0源像素；跑步各方向分别为10、16、0、8源像素，1.75倍镜头下最大约4.8屏幕像素；另有12个不透明像素触及竖直图集边线，仍需逐帧检查素材落脚线。真人实控的手感验收仍未完成。
