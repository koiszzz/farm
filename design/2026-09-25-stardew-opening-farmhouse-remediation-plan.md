# 新档开局、农场与农舍体验整改计划

调查日期：2026-09-25  
调查范围：新档初始化、玩家角色创建、初始农场与农舍；只读检查现有脚本、地图数据、资产映射、近期运行截图和公开参考资料。本轮没有修改游戏代码或素材，也没有运行游戏或测试。

## 目标

把“第一次开始游戏”到“醒来、走出农舍、开始农场生活”整理成完整、连贯的体验。视觉与交互以《星露谷物语》的乡村像素表现和节奏作为高保真参照，同时保留花溪的原创角色、地图、家具和素材；不将原作游戏贴图、角色图集或地图直接导入项目。

本计划只处理开局体验的垂直切片，不要求本阶段重做已经存在的五区域、NPC、钓鱼、矿洞或全年经济系统。

## 现状调查

### 新档与角色创建

- `Main.tscn` 直接启动 `scripts/game.gd`。`_ready()` 构建世界后，先将玩家放到当前户外地图出生点；创建器随后创建且默认隐藏。没有存档时没有显式的新档确认或角色创建步骤。
- `scripts/character_creator.gd` 是可随时打开的外观弹窗；代码注释也注明开局不强制创建。当前字段是肤色、头发、五官和服装选项，不包含姓名、农场名、性别/称谓、农场类型或宠物选择。
- `scripts/game.gd::_save_game()` 将外观写入 `appearance`；确认外观后保存。没有保存独立的玩家档案或新档初始化状态，也没有由玩家确认后一次性建立完整开局数据的入口。
- `scripts/farm_state.gd` 默认开局资源为 100 金币与四种种子；快捷栏预置 8 类工具。HUD 在进入游戏后立即呈现日期、资源、提示与快捷栏。

### 农场与玩家落点

- `design/maps/outdoor_navigation_v1.json` 中初始农场为 `64×44` 格，出生点 `(17,16)`；游戏默认从农场户外开始，而不是先在农舍醒来。
- 当前农场场景和正面农舍资产已具备。近期运行截图显示农舍立面在初始镜头上沿被裁切，角色比例明显偏小，操作说明与底部快捷栏占去大量画面。当前地图还有较大草地、成组田地与路径，后续应围绕开局镜头和第一段行动路线整体重排，而非只换一张房屋图。
- 玩家运行资产已有四方向行走、独立跑步、待机与动作资源；`avatar_renderer.gd` 负责外观组合。创建器源图与当前动画契约之间还需要逐动作、逐服饰确认一致性，不能只看静态头像选项数量。

### 初始农舍

- `farmhouse_interior` 导航区是 `36×20` 格，出生点 `(18,16)`。`world_renderer.gd::_draw_room()` 以程序绘制木地板、墙、窗与门毯；当前路径未引用 `assets/art/concepts/farmhouse_interior_key_art_v1.png`。
- 首始地图已布置床、书架、壁炉、厨房、炉灶、餐桌、椅子、箱子与盆栽，空间表现为较大的完整住宅，而不是一个可随进度扩展的初始单间。
- 家具图集和床、箱子、壁炉的交互已经接入。睡觉、存储和制作等玩法已有挂接点；整改需要复用这些入口，并让实际首日布局与碰撞/可达数据同步。
- 当前室内可见截图证据不足：目录中的 `farmhouse_interior_key_art_v1.png` 是概念图，不是运行画面；本轮也未启动当前游戏，因此本计划不把概念图当作现有游戏效果。

## 与参考体验的主要差距

1. **开局顺序不同**：没有“新档设置 → 角色确认 → 开场叙事 → 农舍醒来 → 出门见到农场”的闭环；启动即进入户外场景。
2. **创建决策不完整**：只有外观小弹窗；缺少姓名、农场命名、开局偏好和地图/农场类型选择的统一呈现与确认。
3. **玩家图像与场景比例不统一**：角色已经有多方向动作，但开局户外画面里人物偏小、农舍被裁切，HUD 抢占注意力，难以建立玩家与农场的关系。
4. **初始房屋成长曲线被跳过**：一开始就有厨房、餐桌、书架等多功能家具，农舍缺少“简陋但可生活、以后逐步扩建”的起点。
5. **素材治理没有贯通概念到运行时**：现有概念图未被当前房间绘制使用；要先确立可复用的地砖、墙体、家具与碰撞/交互契约，再决定概念图哪些部分转为独立原创资产。

## 分阶段整改

### 阶段 0：锁定参考基准与开局验收图

- 依据官方截图与游戏说明建立一页“开局视觉/交互基准”：固定视口、镜头倍率、玩家高度、农舍完整可见范围、可操作地面比例、HUD 占屏、室内房间范围、门和床的位置。
- 记录参考截图的构图与层级规律，而非把截图临摹成可运行贴图；为花溪绘制自己的农场和家具素材清单，注明来源、授权和用途。
- 从当前运行版本采集一致条件下的户外出生帧、农舍整室帧、角色四向帧和初次入屋/出屋帧，作为改造前对照。

**交付：** 开局对照板、素材清单和可量化验收项。

### 阶段 1：建立明确的新档生命周期

- 增加“继续游戏 / 新建农场”的入口；首次运行与显式新档走同一条初始化流程，已有档继续保持原地图、位置和外观。
- 把初始化拆成可检查的步骤：档案输入、外观预览、开局偏好确认、创建初始农场数据、播放简短原创开场、在农舍床边生成玩家、开放移动与互动。
- 玩家按下“开始”后才提交新档；退出创建界面或确认前不覆盖已有存档。新旧存档字段向后兼容，并提供版本迁移和备份。
- 新档设置优先包含姓名、农场名与默认农场方案；称谓、宠物、额外规则是否加入，依据花溪现有玩法决定，不为了照抄原作而增加无效选项。

**交付：** 可重复的新档流程、档案数据结构和旧档兼容方案。

### 阶段 2：重做角色创建和玩家素材体系

- 将目前单独的外观弹窗纳入新档向导；保留之后从角色卡重新编辑外观的能力。
- 以同一角色预览实际游戏里的正面、背面、左右侧面和至少一组走路/工具动作；验收服装、发型、肤色在帧切换时不穿帮、不跳锚点。
- 先确定主角头身比例、轮廓、发色/肤色范围、基础服装剪影、脚底锚点、动作帧尺寸和 nearest 像素缩放，再扩充可选内容。选项数量以每个选项拥有完整运行时动作覆盖为准。
- 将源图、导出图、图集元数据和运行时映射分层维护；每套衣服和可见配饰必须覆盖行走、待机、工具动作和遮挡，不将未完成的静态选项当作完整可选项。

**交付：** 统一角色创建页面、经运行时验证的主角资产契约和素材映射。

### 阶段 3：建立“第一天”的农场布局与镜头

- 将起点从户外出生调整为农舍床边，起床后保留一次可控的室内移动；由玩家从正门进入户外，完整看到农舍立面和首块可耕地。
- 围绕开局任务组织短动线：农舍门 → 初始田地与基础工具 → 邮件/委托或出货设施 → 可扩展空地。让每个可见物件对应第一天能做的事，空地为建设留白。
- 校准农舍、玩家、树木、田块和门的视觉尺寸，确保出生镜头不裁切房屋，也不把大面积重复地表纹理放在视觉中心。
- HUD 在首次教学时按需显示；移除持续占据世界视野的长操作说明，让提示围绕当前动作出现，并确保玩家可以关闭或重看。
- 相机倍率与位置以首个可操作画面和农舍门口同屏构图确定，不把全局放大作为唯一办法。

**交付：** 可从床边完整走出并开始种植的首日农场切片。

### 阶段 4：重做初始农舍与后续升级入口

- 把首级农舍收敛为温暖、朴素、紧凑的单间：床、壁炉/取暖装置、少量个人物件和可交互出口；先明确本项目初始房屋实际需要保留的功能，再将厨房、餐桌等安排到后续房屋升级或解锁节点。
- 以原创模块化资产重做地板、墙面、窗、门、床、炉具、地毯和少量装饰；概念图只作为配色/构图参考，不直接拉伸成整个运行房间背景。
- 建立家具的统一数据表：绘制尺寸、脚底排序锚点、碰撞占格、可交互格和交互目标同源配置；装修变化不得堵住床、门或基本通路。
- 为农舍定义最小成长路线：初始单间 → 解锁厨房/储物等功能 → 扩房或装修。价格、材料、工期由现有经济系统平衡，不直接照搬原作数值。

**交付：** 一间可走、可互动、可扩建且资产/导航一致的初始农舍。

### 阶段 5：整体验收与存档回归

- 用隔离存档覆盖首次启动、完成角色创建、首次进入农场、床边醒来、走出门、睡觉跨日、重新启动恢复、旧版存档迁移和拒绝覆盖已有档。
- 在目标窗口与目标显示设备实机检查：户外全景、房屋立面、四向角色、走跑切换、室内床与门的可达性、遮挡顺序、操作提示、镜头边界和快捷栏占屏。
- 每次只以同样地图、季节、时间、镜头与HUD状态和参考截图并排比较；记录缺陷对应的资产/脚本/地图数据，不靠主观“像/不像”作为唯一结论。
- 将静态资产检查、存档/地图自动检查、真实键盘走通和游戏 framebuffer 视觉确认分别留证；不能把 headless 检查当成实机观感验收。

## 建议实施顺序

先完成阶段 0 与阶段 1 的数据/流程设计，再做阶段 2 主角、阶段 3 农场首日、阶段 4 农舍，最后统一按阶段 5 验收。理由是角色选择、起始位置、房间功能和资产尺度互相约束；先画一批家具再决定初始房屋布局容易返工。

首个可玩里程碑定义为：**新建存档 → 完成原创角色创建 → 在紧凑农舍床边醒来 → 自由走出完整可见的农舍 → 在第一块田地完成一次耕作/播种 → 睡觉并在次日从存档恢复。**
